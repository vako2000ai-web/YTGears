# Решения и открытые вопросы

Дата: 18 октября 2026. Приоритет: текущее задание пользователя и актуальные документы v1.2. В репозитории до начала реализации других требований не найдено.

## Утверждено и реализовано в ядре

- Первая ступень в базе: 12 с/оборот. Исходное T=1800 с; N и T задаются перед раундом.
- Расчётное отношение определяется N и T; прежнее обязательное 2:1 не используется.
- Единое накопленное τ, непрерывные углы при смене скорости, согласованные скорости остальных ступеней.
- Базовый режим: один зритель, без донатов, M=1.
- Один USD даёт донатный множитель ×2; платежи учитываются только подтверждёнными событиями с уникальным ID.
- Один финал, ограничение прогресса, фиксация итогов при логическом контакте, недоступные уникальные показатели обозначены как недоступные.

## Предварительные решения только для проверки

| Вопрос | Реализованная настройка | Статус |
| --- | --- | --- |
| Зрительская формула | `1 + viewerSlope × max(0,V−1)`, по умолчанию slope=0.1 | Не утверждена |
| Сглаживание | Линейный переход за 2 с при смене целевого значения, включая возврат к базе | Форма и длительность не утверждены |
| Потеря данных | TTL=30 с; `null` немедленно запускает плавный возврат к ×1 | Числа не утверждены |
| Накопление донатов | По умолчанию `SingleBoost`: активная сумма от 1 USD даёт один ×2, без дальнейшего роста | Предварительная трактовка, не продуктовая договорённость |
| Альтернативное накопление | `WholeDollarsDoubling`: `2^floor(active USD)` | Только явный экспериментальный выбор |
| Дробные USD | Суммируются точно через decimal; в эффект входят по достижении полного USD | Не утверждено |
| Длительность | По умолчанию до конца раунда; опционально отдельный срок для каждого платежа | Не утверждено |
| Ограничение | Общий множитель ограничивается ×64, параметр `maximumMultiplier` | Значение не утверждено; видимо в выводе |
| Нулевой онлайн | Механизм продолжает базовое движение ×1 | Предварительно |
| Поздние платежи | `RoundClosed`, без изменения итогов и без переноса | Перенос не утверждён |

Предел скорости имеет приоритет над произведением множителей: при уже большом зрительском ускорении дополнительный USD может не удвоить фактически применяемую скорость. Это явно отмечаемое следствие **неутверждённого** ограничения. Базовая проверка 1 USD при одном зрителе даёт ровно ×2. До реального эфира необходимо утвердить совместное правило предела и донатного обещания.

## Требует решения перед реалистичной сценой

1. Движок: рекомендация Unity HDRP, альтернативой остаётся Unreal. Версии, лицензирование, целевая ОС/ПК, GPU, разрешение и FPS ещё не выбраны.
2. Значение N: число видимых колёс или расчётных валов/ступеней? Сейчас сохранено N расчётных периодов; геометрический кандидат может потребовать больше колёс.
3. Что важнее при конфликте: точное T, равномерное q, число колёс, компактность, физическое зацепление? Необходим явный допуск/ограничение набора параметров.
4. Как совместить отпускание защёлки, время движения молоточка и контакт на τ=T, в том числе при сильном ускорении? Пока тестируется логическое событие.
5. Конкретная формула зрителей, частота опроса, сглаживание и поведение при потере источника.
6. Платёжный сервис, подтверждение, длительность эффекта, накопление, дробные суммы, возвраты/отмены, предел и поздние платежи.
7. Реальный источник уникальных зрителей за границы конкретного раунда. До его появления выводить «недоступно».
8. Автоматический перезапуск, смена ваз и повтор в замедлении остаются предложениями. В текущей реализации их нет.
