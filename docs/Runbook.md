# Запуск Python 3D

## Обычный запуск на Windows

Нужен Python 3.11+ и видеодрайвер с OpenGL 3.3. Откройте `C:\Work\YTGears\start.bat` двойным щелчком. При первом запуске создаётся `.venv` и устанавливаются закреплённые зависимости из `requirements.txt`; при следующих запусках открывается приложение. Компиляция и .NET не нужны.

```powershell
cd C:\Work\YTGears
.\start.bat
```

Быстрый демонстрационный режим:

```powershell
.\start.bat --demo
```

Он запускает N=5, T=180 и 51 имитируемого зрителя, то есть Mview=6 после двух секунд сглаживания. Время до удара около 30.83 с. Это имитация, без реальных денег и YouTube.

После подготовки окружения можно запускать непосредственно Python:

```powershell
.\.venv\Scripts\python.exe run.py --gears 8 --seconds 1800
```

По умолчанию один имитируемый зритель, ноль донатов, первый оборот за 12 с, контакт через 30 минут активного времени. Приложение начинает вращение сразу. Ручная пауза останавливает активное время; это операторский инструмент прототипа.

## Передача

N — число расчётных валов, физических колёс 2(N−1). 3D поддерживает N=2..12 и только такие T, для которых найден компактный вариант с целыми зубьями 12..120. Гарантированные стартовые наборы: N=8,T=1800 и N=5,T=180. T должно быть больше 12. Равномерное q в 3D не навязывается: точное общее T обеспечивается неравномерными рациональными ступенями. Это отличие явно обозначено в архитектуре и решениях.

## Предварительные политики

`SpeedPolicy` в `ytgears/core.py`: viewer_slope=0.1, viewer_transition_seconds=2, viewer_timeout_seconds=30, maximum_multiplier=64, donation_rule=SingleBoost, donation_duration_seconds=None. Их можно задать при создании раунда; изменение не меняет уже начатый раунд.

`SingleBoost`: активная сумма USD ≥1 даёт один ×2 без дальнейшего накопления. `WholeDollarsDoubling` включает экспериментальное `2^floor(active USD)`. Ограниченный срок удаляет каждый платёж из активной суммы по своей границе, но не уменьшает полученную общую сумму и число платежей. Предел ×64 применяется к общему произведению, поэтому дополнительный донат при достижении предела не обещает фактическое удвоение. Правила до реального эфира необходимо утвердить.

## Автономные JSON-сценарии

Это отдельный режим, не обычный запуск приложения:

```powershell
.\.venv\Scripts\python.exe run.py --simulate examples/interactive.json
.\.venv\Scripts\python.exe run.py --simulate examples/interactive.json --json
```

Старые camelCase-поля сохранены: `roundId`, `gearCount`, `targetSeconds`, `stepSeconds`, `policy`, `events`. Политики: `viewerSlope`, `viewerTransitionSeconds`, `viewerTimeoutSeconds`, `maximumMultiplier`, `donationRule`, `donationDurationSeconds`.

События: `{ "atSeconds":10,"type":"viewers","viewers":11 }` либо `{ "atSeconds":20,"type":"donation","id":"p1","amountUsd":1 }`. Provider по умолчанию `simulator`, валюта USD, confirmed=true, roundId текущий. `viewers:null` — источник недоступен; 0 — наблюдаемый ноль. Неизвестные поля отклоняются. Входные денежные JSON-числа читаются как Decimal; **в JSON-выводе суммы строковые**, чтобы не терять точность. Поля отчёта теперь в Python snake_case.

События выполняются в точное указанное время, при равных временах — в порядке массива. Контакт имеет приоритет над платежом ровно в момент τ=T. Донаты после финала возвращают RoundClosed и не переносятся. Режим JSON сохраняет математическую равномерную передачу, не выдавая рациональную оценку за геометрию сцены.

## Встраивание ядра

```python
from ytgears import MechanismRound, RoundParameters, SpeedPolicy, Donation

round_ = MechanismRound("round-1", RoundParameters(8, 1800), SpeedPolicy())
round_.observe_viewers(1)
round_.receive_donation(Donation("round-1", "confirmed-provider", "payment-1", "1.00"))
contacted_now = round_.advance(delta_seconds)  # реальные монотонные секунды, без внешнего умножения на M
angle = round_.transmission.angle_degrees(0, round_.mechanism_seconds)
if contacted_now:
    round_.begin_destruction()
    # Один запуск разрушения и звука; result уже заморожен.
# По завершении клипа: round_.complete_destruction()
```

Сумму передавать Decimal, строкой или целым; float-деньги отклоняются. Параметры и итог — неизменяемые объекты. Хост однопоточный; перед каждым событием сначала продвигает время. Реальное подтверждение платежа и устойчивый журнал обязан предоставить будущий адаптер.

## Ограничения

Сцена процедурная, разбиение регулярное, разрушение runtime Bullet. Не подключены реальные платежи/YouTube. Настоящий контакт и физический шарнир молоточка не моделируются; синхронизация задана фазой. Целевые FPS/ПК и финальная художественная приёмка пока не утверждены. Звуки синтезированы локально. Перезапуск вручную, сохранения раундов нет.
